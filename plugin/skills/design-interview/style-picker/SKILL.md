# Style Picker

"예쁘게 만들어주세요"는 AI에게 아무 정보도 아니다. 이 스킬은 업종/목적을 스타일 이름 하나로 번역해서, 이후 디자인·구현 단계(design-system-docs, ui-ux-pro-max, taste-skill, impeccable)가 흔들리지 않게 만드는 앞단 스텝이다.

## 언제 쓰는지

- 웹/앱을 새로 만들거나 리디자인하기 전, 스타일 방향이 아직 정해지지 않았을 때
- 사용자 요청이 "예쁘게", "고급스럽게", "깔끔하게", "전문적으로" 같은 형용사뿐일 때
- 이미 고른 스타일이 업종/타깃에 맞는지 검증이 필요할 때

## 언제 안 쓰는지

- 스타일이 이미 명확히 정해진 상태에서 컴포넌트만 구현하면 될 때 → 바로 `ui-ux-pro-max`(색상/폰트/컴포넌트 세부 결정) 또는 `design-system-docs`(와이어프레임)로
- 브랜드 톤 자체를 처음부터 새로 만들어야 하는 고난도 판단 → `taste-skill`
- 완성된 화면의 품질을 점검/개선 → `impeccable`

## Workflow

### Step 1 — 업종·타깃 확인

불명확하면 사용자에게 묻는다: 어떤 업종/서비스인지, 고객이 이 페이지에서 가장 먼저 확인하고 싶은 게 무엇인지(신뢰감? 트렌디함? 기억에 남는 인상?).

### Step 2 — 카탈로그에서 매칭

`references/style-catalog.md`를 읽고 세 카테고리 중 하나로 좁힌다:

| 카테고리 | 고객이 먼저 보는 것 | 대표 스타일 |
| --- | --- | --- |
| 신뢰감·전문성 | "믿을 만한 곳인가" | 미니멀리즘, 에디토리얼, 벤토 그리드 |
| 세련됨·트렌디함 | "요즘 감각 있는 곳인가" | 글래스모피즘, 그라디언트 메시, 다크모드, 뉴모피즘 |
| 개성·임팩트 | "기억에 남는가" | 브루탈리즘, 레트로·Y2K, 3D 인터랙티브 |

카탈로그 표에서 업종이 일치하는 줄을 찾아 스타일 후보를 1~2개로 좁힌다. 타깃이 불명확한 업종(예: 법률+2030 타깃처럼 카테고리가 충돌하는 경우)은 신뢰감 카테고리를 기본값으로 하고 사용자에게 확인한다.

### Step 3 — 스타일 하나로 확정

**절대 두세 개를 섞지 않는다.** 섞으면 정리 안 된 인상을 준다. 후보가 여러 개면 사용자에게 실제 사이트 예시(카탈로그에 포함)를 보여주고 하나를 고르게 한다.

### Step 3.5 — 검증된 템플릿이 있으면 먼저 띄워서 적용 여부를 묻는다

`references/template-references.md`의 표에서 확정한 스타일 또는 요청한 화면 종류(대시보드, 히어로 이미지 등)와 맞는 템플릿을 찾는다.
맞는 게 있으면 새로 만들기 전에 다음 순서로 보여 준다. 이미 돌려 본 결과물을 고르게 하는 편이 백지에서 스타일을 설명하는 것보다 사용자 판단이 빠르고 정확하기 때문이다.

1. 한 줄 안내: "이 스타일로 바로 쓸 수 있는 템플릿이 있습니다."
2. 미리보기 이미지(`references/assets/templates/…`)를 사용자에게 보여 준다(`SendUserFile` 등 파일·이미지 전달 수단이 있으면 그것으로, 없으면 경로와 artifact 링크).
3. 템플릿마다 2~3줄 요약: 무엇인지, 연결 스타일, 적용하면 바뀔 부분.
4. `AskUserQuestion`으로 **"이 템플릿을 적용할까요?"** 를 묻는다. 선택지:
   - **적용** — 템플릿 원본(`references/templates/…`)을 프로젝트에 복사하고, 브랜드명·색·데이터만 교체한다.
   - **참고만** — 레이아웃·질감·토큰만 참고하고 새로 만든다.
   - **사용 안 함** — 템플릿 없이 Step 4로 진행한다.
   맞는 템플릿이 여러 개면 한 질문에 선택지로 나란히 둔다(템플릿 A 적용 / 템플릿 B 적용 / 참고만 / 사용 안 함).

맞는 템플릿이 없으면 이 단계를 말없이 건너뛴다. "템플릿이 없습니다"라고 알릴 필요는 없다.
비대화형 실행이면 묻지 않고 "참고만"으로 진행한 뒤 그 가정을 결과에 적는다.

### Step 4 — 모호한 요청 → 실행 가능한 프롬프트로 변환

확정한 스타일을 다음 패턴으로 구체화해서, 이후 디자인/구현 스킬이나 AI 프롬프트에 바로 넘긴다.

| 모호한 요청 | 구체화된 지시 |
| --- | --- |
| "깔끔하고 전문적으로" | 여백 넓은 미니멀 스타일, 큰 제목 + 흰 배경 중심 |
| "고급스럽게" | 다크모드 + 포인트 컬러 하나, 글래스모피즘 카드 |
| "정보를 잘 정리해줘" | 벤토 그리드 레이아웃, 카드로 정보 분할 |
| "친근하게" | 밝은 그라디언트 배경, 둥근 모서리 카드 |

### Step 5 — 체크리스트

- [ ] 스타일이 하나로 통일됐는가 (두세 개 혼합 금지)
- [ ] 효과가 가독성을 해치지 않는가 (해치면 효과를 뺀다)
- [ ] 모바일 화면 기준으로 먼저 확인했는가
- [ ] 경쟁사 3곳을 봤는가 (다 비슷하면 차별화, 제각각이면 가장 깔끔한 쪽)

### Step 6 — (선택) 2026 트렌드 레이어

기본 스타일이 정해진 뒤 포인트로만 얹을 수 있는 흐름은 `references/style-catalog.md`의 "2026 트렌드" 표 참고 (레이어/깊이감, 스크롤텔링, 마이크로 인터랙션, Y2K 재등장, 유동형 레이아웃). 트렌드를 다 따라갈 필요는 없고, 업종에 맞는 것 하나만 제대로 쓰는 게 낫다.
